## OVERVIEW

Vike SSR framework + Vue 3 Composition API + Effector state management. Full-stack TypeScript app with Telefunc for server calls.

## STRUCTURE

```
vike-vue-effector/
├── pages/          # Vike page routes (+Page.vue, +config.ts)
├── components/     # Reusable Vue components
├── layouts/        # Page layout wrappers (LayoutDefault.vue)
├── utils/effector/ # Effector helpers (useUnit, scope management)
├── services/app/   # Global app state service
├── server/         # Express entry + handlers (telefunc, vike)
└── assets/styles/  # Global styles
```

## WHERE TO LOOK

| Task           | Location                        | Notes                    |
| -------------- | ------------------------------- | ------------------------ |

| App entry      | `server/entry.ts`               | Express middleware setup |

## CONVENTIONS

**File Naming (Vike-specific):**

- `+Page.vue` — Page component (required)
- `+config.ts` — Page configuration (optional but used here)
- `+onPageTransitionStart.ts`, `+onPageTransitionEnd.ts` — Animation hooks
- `<name>/model.ts` — Per-page Effector state

**Effector Patterns:**

- `utils/effector/useUnit()` — Bind stores/events to components with scope awareness
- `Provider` in `LayoutDefault.vue` — App-wide scope provider
- Split `$counterServer` (SSR) vs `$counterClient` (hydration-safe) stores

**Path Aliases (tsconfig.json):**

```
@/*              → ./*
@utils/*         → ./utils/*
@services/*      → ./services/*
@layouts/*       → ./layouts/*
@components/*    → ./components/*
```

## Development Guidelines

### State Management
- Create models in `model.ts` files within page directories
- Use `createPageInit()` for server-side data preparation
- Use `createPageStart()` for client-side initialization
- Always use the custom `useUnit` hook instead of the standard one

### Page Structure
- Each page should have its own directory under `/pages/`
- Use `+pageInitiated.ts` for server-side effects
- Use `+pageStarted.ts` for client-side effects
- Page components go in `+Page.vue`

### Component Development
- Components use Vue 3 Composition API
- Import Effector units via `useUnit` hook
- Follow the established alias pattern for imports

### RPC Communication
- Use Telefunc for client-server communication
- RPC functions in `.telefunc.ts` files
- Type-safe by default

### ANTI-PATTERNS (THIS PROJECT)

- **DO NOT** create standalone store files outside `services/` or page models
- **NEVER** use `store.getState()` on client — always `useUnit()` for reactivity
- **DON'T** modify `dist/` — generated by build
- **AVOID** direct Effector imports in Vue components — prefer `@utils/effector`

### UNIQUE STYLES

- Telefunc integrated at `/api/_data` for server function calls
- SSR + client hydration sync via scope merge patterns

### Linting and Code Style

- **ESLint config**: Modern flat config in `eslint.config.js`
- **Prettier integration**: Single quotes, trailing commas
- **Import sorting**: Enforced via `simple-import-sort`
- **TypeScript**: Strict type checking with consistent import types
- **Vue-specific rules**: Component naming, attribute ordering

### SSR Considerations
- SSR is enabled by default
- State is serialized on server and hydrated on client
- Use Effector scopes for proper SSR state isolation
- Page transition animations supported via lifecycle hooks
